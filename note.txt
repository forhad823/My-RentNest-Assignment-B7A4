model Payment {
  id                    String        @id @default(uuid())
  amount                Float // Total amount paid
  currency              String        @default("usd")
  status                PaymentStatus @default(PENDING)

  // Stripe Checkout Session ID (cs_...). Used to find this record when webhook fires.
  stripeSessionId       String?       @unique @db.VarChar(255)

  // Stripe Payment Intent ID (pi_...). Available after checkout completes. Useful for refunds.
  stripePaymentIntentId String?       @unique @db.VarChar(255)

  // Hosted receipt URL from Stripe — no need to build receipts manually
  stripeReceiptUrl      String?       @db.Text

  // Card brand / payment method (e.g. "visa", "mastercard")
  paymentMethod         String?       @db.VarChar(50)

  paidAt    DateTime?
  createdAt DateTime  @default(now())
  updatedAt DateTime  @updatedAt

  rentalRequestId String
  rentalRequest   RentalRequest @relation(fields: [rentalRequestId], references: [id], onDelete: Cascade)

  @@index([rentalRequestId])
  @@index([stripeSessionId])
  @@index([stripePaymentIntentId])
  @@map("payments")
}
                                                                                                                                                  
  ### Why this is very easy to integrate:
  
  1. Checkout session linking: The stripeSessionId allows a developer to save the Stripe Checkout Session ID (session.id) as soon as the checkout endpoint  
  /api/payments/create is triggered.
  2. Webhook execution: When Stripe calls the webhook callback (/api/payments/confirm), the developer can retrieve the checkout session payload, find the   
  corresponding DB record by looking up stripeSessionId, and instantly match it.
  3. Traceability: The stripePaymentIntentId captures the final charge ID (pi_...) for refunding/referencing later, and stripeReceiptUrl links directly to  
  Stripe's hosted PDF receipt page, eliminating the need to construct receipts manually.
